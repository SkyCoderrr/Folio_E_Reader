# Codex backend feasibility review — contract 0.1.0

Reviewed 2026-11-09 against all existing `contract/` files, including examples, and PRD §§6.8, 9, 10, 12 and 13 M0–M3. This is a proposal to Dany_PM, not a contract amendment. No implementation or Windows UI spike was performed. **Verdict: feasible on stable Rust/Tauri v2, subject to the BLOCKER and CHANGE items below; do not acknowledge v0.1.0 unchanged.**

1. **[NOTE] M0–M3 coverage: all 23 command shapes and all six associated event shapes are implementable.**
   M0: `app_info`, `app_quit`, `window_get_state`, `window_minimize`, `window_toggle_maximize`, `window_start_drag`, `window_start_resize`, `window_set_caption_rects`; events `app://close-requested`, `window://state-changed`, `window://caption-state`. M1: `window_set_fullscreen`, `kv_get`, `kv_set`. M2: `settings_get`, `settings_patch`, `settings_set`, `fonts_list`; `settings://changed` is intentionally first emitted in M7. M3: `dialog_pick_books`, `library_import`, `library_list`, `book_get`, `library_remove`, `book_open`, `position_get`, `position_save`; events `import://item`, `import://done`.
   Core window methods, Rust-owned state/files, the dialog plugin and bundled SQLite cover these operations; EPUB/font/hash/image work also needs the stable supporting crates already listed in PRD §10.1. No command intrinsically requires elevation, nightly Rust or Tauri's `unstable` feature. Use `get_webview_window("main")`; for resize, the stable underlying `Window::start_resize_dragging` is available through the webview's owning window. Blocking DB/import/font work belongs off the UI thread. [Tauri window API](https://docs.rs/tauri/latest/tauri/window/struct.Window.html), [webview API](https://docs.rs/tauri/latest/tauri/webview/struct.Webview.html), [dialog](https://v2.tauri.app/plugin/dialog/).

2. **[BLOCKER] M0.6: subclassing only the top-level Tauri HWND is insufficient for HTML Snap Layouts.**
   `HTMAXBUTTON` is the documented prerequisite, but WebView2's child HWND can receive the hit test before the parent. HTML transparency or `pointer-events: none` does not create a native hit-test hole. WebView2 `app-region: drag` support is not proof of a custom maximize region; composition-controller APIs are not a drop-in replacement for Tauri's normal windowed WebView2 host. [Microsoft Snap requirements](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu), [WebView2 composition hit-testing](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2compositioncontroller4).
   **Proposed edit:** in `commands.md/window_set_caption_rects` and `events.md/window://caption-state`, choose a Rust-owned, non-activating native child hit-test overlay above the WebView2 caption region, with a custom WndProc returning `HTMAXBUTTON` over `CaptionRects.maximize`; retain top-level subclassing for frame integration where needed. Make it visually transparent without making it input-transparent: a no-paint/null-brush child is a candidate; zero-alpha layered/click-through windows can lose the hit test. Avoid depending on Chromium child-window class names. Document this as the M0.6 candidate, gated on actual hover flyout, snapping, clicks, no duplicate native painting, hidden chrome and 100/150/200% mixed-monitor DPI tests in ADR-003. [Runnable overlay implementation and reported results](https://github.com/Zbrooklyn/tauri-snap-layouts).
   A “decorum-style” integration must be inspected, not assumed compliant: the currently inspected decorum `show_snap_overlay` synthesizes Win+Z and Alt, contrary to PRD §6.8. Do not adopt that path. Native child HWNDs need neither Tauri `unstable` nor admin rights. [Decorum command source](https://github.com/clearlysid/tauri-plugin-decorum/blob/main/src/commands.rs).

3. **[CHANGE] Caption activation ownership and the close handshake are underspecified.**
   A native overlay consumes pointer events, so React `onClick`/`:hover` will not reliably run. Returning `HTCLOSE` can also route a custom button through `WM_CLOSE`, contradicting the event rule that custom close never emits `app://close-requested`.
   **Proposed edit:** specify in `window_set_caption_rects` that Rust owns pointer activation for overlay-covered buttons: minimize once, maximize/restore once, close through the same `app://close-requested` handshake as native X. Update `events.md` to include overlay close. `window://caption-state` reports painting state only and resets to `{hovered:null,pressed:null}` on capture loss, hide, fullscreen and destruction. Keep `window_minimize`, `window_toggle_maximize` and UI flush→`app_quit` available for keyboard/accessibility activation, without duplicating native pointer activation.

4. **[CHANGE] Caption rectangles need explicit coordinate, ordering and invalidation rules.**
   CSS px equal DIPs only with WebView zoom fixed at 1. Multiplying by monitor scale without the webview/client origin is insufficient; negative screen coordinates on secondary monitors also matter. Overlapping asynchronous updates can resurrect a hidden overlay.
   **Proposed edit:** define `Rect` as unzoomed viewport CSS px, fix WebView zoom at 1, use signed screen coordinates mapped to client space, then DPI conversion once. Define `width,height > 0`, finite coordinates, non-overlap and viewport bounds. Serialize `window_set_caption_rects` calls in the UI; resend after resize/layout/DPI changes and transition completion. Rust disables overlays immediately during fullscreen/native-titlebar mode and on webview reload, regardless of stale rectangles. Define resize zones as **6 CSS px**, not `6 * scaleFactor` CSS px; Rust/Windows performs physical scaling.

5. **[NOTE] Runtime asset scope changes are supported in stable Tauri v2.**
   Enable Cargo `tauri/protocol-asset` and `app.security.assetProtocol.enable`; start with a narrow/empty configured `FsScope`, then call `app.asset_protocol_scope().allow_directory(&library_dir, true)` and likewise for profile `cache` and `library/covers`. This is the core asset scope, not a requirement to install `tauri-plugin-fs`. Add the new library directory before `library_set_folder` returns/publishes it; the contract expressly permits the old grant until restart. Rebuild grants on every launch; grant or recheck newly created directories before serving bytes. `convertFileSrc` only builds a URL and grants no access. [Manager](https://docs.rs/tauri/latest/tauri/trait.Manager.html#method.asset_protocol_scope), [Scope](https://docs.rs/tauri/latest/tauri/scope/fs/struct.Scope.html#method.allow_directory).

6. **[BLOCKER] `library.folder` can currently defeat the “never expose settings/DB” asset boundary.**
   A hand-edited `library.folder = <profile>` or an ancestor such as `C:\` passes the current path shape and causes a recursive grant covering `settings.json` and `library.db`. The M7 guard only excludes paths *inside* cache/covers. This affects M0–M3 startup, not just M7.
   **Proposed edit:** apply one canonical path validator at settings load and `library_set_folder`: reject a library root equal to or an ancestor of `profileDir`, and reject roots within `cache` or `library/covers`; account for junctions/reparse points and path components, not string prefixes. On load repair invalid `library.folder` to null; the command returns `LIBRARY_FOLDER_INVALID`. Tighten `$defs/AbsPath`/native validation to require UNC server **and share** (`\\server` currently passes the regex) and reject device paths/NUL. Ensure scope tests prove profile settings/DB remain denied. `<profile>/library` remains allowed.

7. **[CHANGE] Select the per-profile single-instance implementation now.**
   Stable `tauri-plugin-single-instance` on Windows derives its mutex/event-window names from `app.config().identifier`; `Builder::dbus_id` only affects Linux. Passing a profile hash to the callback does not change identity. [Released 2.5.5 Windows source](https://github.com/tauri-apps/plugins-workspace/blob/single-instance-v2.5.5/plugins/single-instance/src/platform_impl/windows.rs), [builder](https://docs.rs/tauri-plugin-single-instance/latest/tauri_plugin_single_instance/struct.Builder.html).
   **Proposed edit:** choose file-layout.md §3's existing fallback: retain bundle identifier `com.dany.ereader`, use `Local\\<profile-key>` mutex plus a bounded, current-user handoff channel, and do **not** also register the stock identifier-wide plugin. Hold the lock until exit; queue a pending show request if `main` is not created yet. Specify same Windows logon session as the lock scope. Alternative: set generated context `config_mut().identifier = profileKey` before builder initialization, but then explicitly override all profile-derived directories and accept changed runtime identity; do not silently change the identifier. [Context configuration API](https://docs.rs/tauri/latest/tauri/struct.Context.html#method.config_mut).

8. **[CHANGE] Profile resolution has an empty-variable contradiction and needs startup enforcement.**
   README/settings say test profile iff the variable is set; file-layout.md says “set and non-empty,” otherwise real profile. An empty test override could therefore touch the owner's profile.
   **Proposed edit:** `E_READER_PROFILE_DIR` absent = real profile; present but empty/whitespace/invalid/unwritable = native startup error and exit 2, never fallback. Require an absolute local path suitable for both SQLite WAL and WebView2; reject UNC/network profile roots (library roots may remain UNC). Canonicalize once before deriving the lock key, normalizing equivalent path spellings. Resolve paths before initializing any persistence plugin or creating any window. [SQLite WAL network restriction](https://www.sqlite.org/wal.html), [WebView2 UDF guidance](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/user-data-folder).

9. **[CHANGE] Pin the actual WebView2/log/window-state locations, not just the intended profile.**
   **Proposed edit:** create `main` programmatically after profile/settings resolution, using absolute `WebviewWindowBuilder::data_directory(profileDir.join("webview"))`; disable config-driven auto-creation. Explicitly direct logging to `TargetKind::Folder { path: profileDir.join("logs"), ... }` and window-state persistence to `<profile>/window-state.json`. Never rely on default plugin paths; do not restore hidden/minimized/fullscreen state at launch. Narrow “nothing is written under LOCALAPPDATA” to app-controlled persistence/UDF; shared WebView2 runtime/Windows maintenance is outside this guarantee. [Webview builder](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindowBuilder.html#method.data_directory), [logging targets](https://docs.rs/tauri-plugin-log/latest/tauri_plugin_log/enum.TargetKind.html), [window-state flags](https://docs.rs/tauri-plugin-window-state/latest/tauri_plugin_window_state/struct.Builder.html).

10. **[CHANGE] Browser accelerator suppression is feasible, but is not a universal keyboard guarantee.**
    Use stable `with_webview` on the main thread and WebView2 `ICoreWebView2Settings3::put_AreBrowserAcceleratorKeysEnabled(false)` in release, plus zoom hotkeys disabled. Pin compatible Tauri/WebView2 COM bindings; Tauri warns platform binding versions can change across minor releases. Editing/navigation accelerators remain enabled unless handled; OS-reserved keys and IME do not all reach JavaScript. The UI still needs its key router/IME guards. [WebView2 settings](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2settings3), [Tauri escape hatch](https://docs.rs/tauri/latest/tauri/webview/struct.WebviewWindow.html#method.with_webview).
    **Proposed edit:** replace commands.md's “every key reaches the UI's key router” guarantee with “browser-specific shortcuts are disabled in release; local `keybindings` still require DOM cancellation and IME handling, and OS-reserved shortcuts are excluded.”

11. **[NOTE] Serde output names, nulls and enum representation otherwise align.**
    All inspected struct field names map correctly to TS camelCase, including `txtPrefs`, `txtCjk`, `northEast`, `first20` and `builtIn`. Unit enums serialize as strings, with the explicit `sans-serif`/encoding/action-id renames matching TS; no tagged-enum wrapper is needed. Non-skipped `Option<T>` emits null for `Locator`, `BookRecord`, etc.; `AppError.details` and style patch `None` are omitted. Fractional progress, typography, speed, scale and rectangle fields use `f64`; integer fields use integer Rust types. `Keybindings = BTreeMap<ActionId, Vec<Chord>>` correctly represents a **sparse** TS map; fix the equivalence table's misleading `Record<ActionId,...>` wording to `Partial<Record<ActionId,...>>` when revising it.

12. **[BLOCKER] TS `MergePatch<T>` cannot express its own documented nested reset under strict null checks.**
    `ReadingStylePatch.font` is optional, so `T[K]` includes `undefined`; its `extends object` test fails and leaves `StyleFontPatch` unchanged. Thus `SettingsPatch = {styleOverrides:{font:{size:null}}}` is rejected by the advertised TS type, while the example and Rust `Value` accept it.
    **Proposed edit:** replace the helper in `types.ts` with `type MergePatch<T> = { [K in keyof T]?: NonNullable<T[K]> extends readonly unknown[] ? NonNullable<T[K]> | null : NonNullable<T[K]> extends object ? MergePatch<NonNullable<T[K]>> | null : T[K] | null };`. Preserve `SettingsPatch`/`TxtPrefsPatch` names. Add a strict TypeScript compile check assigning `examples/settings_patch.json`'s nested reset and negative checks for invalid leaf values.

13. **[CHANGE] Rust deserialization domains are broader/narrower than the TS/schema contract.**
    `Style*Patch`/`ReadingStylePatch` accept explicit null as `None`, but their TS fields/schema permit omission, not null, in a complete `Settings`; `PagesPerView = u8` accepts 0/3, `Settings.version: u32` accepts 2, and string aliases/`Value` do not enforce patterns or object shape. Required nullable `Option` fields also accept omission, as rust-types.md already acknowledges. These are validation gaps, not output casing errors.
    **Proposed edit:** require raw-JSON schema validation for `settings_set.settings` **before** conversion into `Settings`, allowing a raw `Value` command boundary exception in rust-types.md. Validate `settings_patch.patch` as an object, reject `version`/unknown paths even when their value is null, apply deletion/default restoration, prune empty override groups, then validate. Reserve null resets for merge-patch input. Specify whether missing nullable `Locator.cfi`/`globalCharOffset` is rejected or intentionally tolerated; recommend reject at the raw argument boundary to honor “always present.” Use the raw validation path to return `SETTINGS_INVALID.issues` instead of an early Tauri string/`IPC_ERROR` for invalid settings bodies.

14. **[CHANGE] `deny_unknown_fields` on the sample `*Args` structs does not validate real invoke envelopes.**
    The prescribed Tauri signatures extract separately named parameters; their unused test-only args struct cannot reject extra top-level keys. For example, `{bookId, typo:true}` may be ignored even though errors.md claims rejection.
    **Proposed edit:** in rust-types.md and errors.md, state “unknown nested fields are rejected; unknown top-level invoke keys are ignored by standard named-parameter dispatch,” or explicitly require custom envelope validation. Recommend the former, keeping current flat command shapes. Preserve Tauri deserialization failures → UI `IPC_ERROR`, and domain validation → backend `INVALID_ARGUMENT`.

15. **[CHANGE] Numeric/character units need explicit cross-language limits.**
    TS `number` cannot exactly represent every Rust `u64`/`i64`; SQLite INTEGER is signed 64-bit, and DB bindings need checked conversions. “Characters” also differs between JS UTF-16 indices, Rust scalar counts and SQLite `length()`.
    **Proposed edit:** require `Number.isSafeInteger` equivalents for all integer IPC values: unsigned values ≤ `9007199254740991`, `UnixMs` within ± that bound, plus the existing narrower field ranges. Add `maximum: 9007199254740991` to `Preset.updatedAt` in the settings schema and checked `u64`↔`i64` DB mapping rules. Define `Locator.charOffset`, `globalCharOffset`, `TxtSection.startChar/chars`, `totalChars` as **UTF-16 code units**, matching DOM text offsets; define bounded display strings such as `snippet`/preset names as Unicode scalar counts, with a non-BMP example. Distinguish JSON Schema's mathematically integral `20.0` from serde integer-token parsing; valid JS integer values serialize as integer tokens.

16. **[CHANGE] SQLite primary keys and declared types do not enforce the stated invariants.**
    Executing the SQL confirmed `books.id = NULL`, `positions.book_id = NULL` and fractional `books.file_size = 1.5` are accepted. Non-INTEGER primary keys in ordinary SQLite tables do not imply NOT NULL; NULL also passes a CHECK whose result is NULL. `json_valid` accepts scalar `null` as a locator. [SQLite constraints](https://www.sqlite.org/lang_createtable.html).
    **Proposed edit:** add explicit `NOT NULL` to `books.id`, `book_prefs.book_id`, `positions.book_id`; make the five tables `STRICT` (all current declared types are supported), or add equivalent `typeof` checks for integer columns. Require `json_type(locator_json) = 'object'` and object `meta_json`; continue validating full `Locator` structure in Rust. Calendar validity and `active_ms <= ended_at-started_at` need command validation; the `local_day` GLOB alone admits invalid dates. Bundled modern SQLite supports these changes and the existing JSON functions.

17. **[CHANGE] Bookmark “gets a new id” is false with the current schema.**
    A delete/add probe reused rowid `1`. `INTEGER PRIMARY KEY` can reuse deleted ids, so a stale `bookmark_remove` can target a later bookmark. This is future M5 behavior, but the table is created in M3. [SQLite rowid allocation](https://www.sqlite.org/autoinc.html).
    **Proposed edit:** declare `bookmarks.id INTEGER PRIMARY KEY AUTOINCREMENT` to guarantee never reusing automatically allocated bookmark ids, and retain decimal-string `BookmarkId`. No equivalent promise currently requires AUTOINCREMENT on `sessions.id`.

18. **[CHANGE] Migration/version preflight must precede write pragmas; backup wording is too strong.**
    `user_version` and transactional DDL are suitable. But running `journal_mode=WAL` on every startup before checking the version violates “newer DB never opened for writing.” A checkpoint request can be busy/incomplete; blindly copying only the main file can omit committed WAL data. Per-step transactions also preserve earlier successful migrations if a later step fails, contradicting “DB untouched.”
    **Proposed edit:** db-schema.md: inspect existing `user_version` before write-capable connection initialization, reject newer versions before any mutating pragma, and distinguish “opened read-only for inspection” from “not opened.” Back up with SQLite's backup API (`rusqlite` `backup` feature), or verify a complete checkpoint with all app connections quiescent before copying. Specify rollback of the **failing step**, preservation of completed steps and the original backup. Keep immutable numbered migrations separate from the latest `db-schema.sql` snapshot. [SQLite backup API](https://www.sqlite.org/backup.html).

19. **[CHANGE] DB-unavailable behavior conflicts with command error lists/order.**
    `library_import` promises only `INVALID_ARGUMENT`, while errors.md says every DB-backed command rejects `DB_VERSION_UNSUPPORTED`. `book_open` cannot distinguish BOOK_NOT_FOUND/DRM before accessing a usable DB, although DB errors are listed last.
    **Proposed edit:** define precedence as argument validation → DB availability/version gate → row lookup → file/restriction checks → transactional updates. Add `DB_ERROR`/`DB_VERSION_UNSUPPORTED` to `library_import`'s pre-queue errors. After acceptance, any later DB failure is an `import://item.error`, allowing `DB_VERSION_UNSUPPORTED` there if needed. A migration/open failure leaves the shell/settings usable and DB commands predictably disabled; it must not abort window creation without explanation.

20. **[CHANGE] Import traversal failures have no defined item or completion semantics.**
    Missing top-level paths, denied folders and walk errors are not candidate files, yet individual problems must never reject an accepted job and `total` must be fixed before its first item. Also errors.md says “duplicate active jobId” whereas commands.md prohibits all reuse in the process.
    **Proposed edit:** `library_import` performs ordered enumeration in its worker; each unresolved supplied path or failed directory enumeration becomes one synthetic failed candidate with that path, `fileName` = basename, `IO_ERROR`, and counts in `total`. Successfully discovered books still run; skipped symlinks/junctions generate no item. Break case-insensitive sorting ties with exact ordinal names. Define `total = added + duplicates + unsupported.length + failed.length`, contiguous indices and exactly one `import://done` for accepted jobs while the process remains alive. Reject **any previously accepted** `jobId` reuse; update errors.md accordingly.

21. **[CHANGE] A serialized DB writer does not serialize file mutations.**
    Import, `library_remove`, `book_open` and later `library_set_folder` can otherwise race between copying, committing, deleting and returning paths; `added` could describe a copy concurrently deleted by removal.
    **Proposed edit:** define one library mutation queue/lock spanning the complete per-book import pipeline, the entire `library_remove` operation and `library_set_folder`. Take a consistent snapshot for `book_open`/`book_get`/`library_list`; coordinate lazy prefs creation and open bookkeeping with removal. No lock may be held while awaiting UI event handling. The existing FIFO import order remains unchanged.

22. **[CHANGE] Import rollback promises exceed filesystem/SQLite atomicity.**
    A crash between copy rename and DB commit can leave orphans; a locked file or full disk can defeat cleanup. Step 8 excludes failed `.part` writes before step 4 completes. Hashing once then copying a changed source can also store bytes under the wrong content id.
    **Proposed edit:** amend `library_import` to hash the same bytes staged into `.<id>.<ext>.part`, validate/flush staging, then publish and commit, with best-effort cleanup on all failures. Document that DB+filesystem are not one atomic transaction; reconcile interrupted imports at startup under the library lock using a journal of app-created files. Do not infer ownership or delete originals merely from a hash-shaped filename. An item becomes `added` only after commit; include cleanup failures in logs while retaining the primary `ImportItemPayload.error`. Bound ZIP member extraction/image dimensions so malformed EPUBs cannot exhaust the worker indefinitely.

23. **[CHANGE] `library_remove` needs one batch transaction and complete cleanup reporting.**
    “For each existing book, in one DB transaction” can mean separate commits, which allows a later DB rejection after earlier deletions, contrary to errors.md. `FileError` wording covers only copies although covers/cache deletion can also fail.
    **Proposed edit:** make all unique existing `bookIds` one transaction, commit once, then perform best-effort cleanup; missing files are success. `removedIds` are unique in input order. `fileErrors` includes any copy/cover/cache cleanup failure, one aggregated `FileError {bookId,message}` per affected book. Validate persisted `file_rel_path`/`cover_rel_path` against the generated id-based layout before using them for access/deletion; malformed DB paths return `DB_ERROR`, never escape managed roots.

24. **[CHANGE] EPUB restriction storage cannot represent both conditions and re-open failures lack an error.**
    `meta_json.restriction` is a single `"drm" | "fixedLayout"`, but a book can satisfy both; `book_open` promises DRM precedence. A library copy altered after import can become an invalid ZIP while retaining stale metadata.
    **Proposed edit:** use internal `meta_json.restrictions: {drm:boolean,fixedLayout:boolean}` and check DRM first, then fixed layout. Specify the font-obfuscation exemption URIs when detecting encryption. Add `EPUB_INVALID` to `book_open` for failed EPUB revalidation, and state whether copies are revalidated on open (recommend at least detecting changed size/mtime and reparsing). Only successful opens update `lastOpenedAt`/create default TXT prefs.

25. **[CHANGE] Close/quit is feasible as a bounded, best-effort protocol, not a universal save guarantee.**
    Tauri close prevention plus an async timer works, but blocking the event loop defeats the deadline; SQLite's 5000 ms busy timeout exceeds 3000 ms. JS flush rejection can also prevent a custom-close `app_quit` call forever. Shutdown/logoff/forced termination are distinct from normal `WM_CLOSE`. [Windows session-end rules](https://learn.microsoft.com/en-us/windows/win32/shutdown/wm-queryendsession).
    **Proposed edit:** define `app://close-requested` for ordinary close/quit requests; the UI bounds flushing and calls `app_quit` in `finally`. Rust starts one monotonic 3000 ms deadline without blocking the UI thread, stops accepting new imports, and cancels/drains work only within the remaining budget. State that timeout/session end may lose unacknowledged writes; previously acknowledged writes remain the recovery basis. Log cleanup errors because `app_quit` never rejects. Do not claim `import://done` after process exit or guaranteed JS flushing during forced shutdown.

26. **[CHANGE] Stable boss-key APIs still need platform restrictions and honest rollback semantics.**
    These are M7 commands but explicitly permitted immediately after M0.1. Mapping `Code` tokens is not proof that every physical key is supported distinctly by Windows `RegisterHotKey`: layouts and aliases matter. The inspected backend maps letter codes to VK letters, aliases some international codes and may reject unsupported tokens. Callbacks include press/release, so toggling both would immediately undo hiding. [Windows backend](https://github.com/tauri-apps/global-hotkey/blob/dev/src/platform_impl/windows/mod.rs), [plugin](https://docs.rs/tauri-plugin-global-shortcut/latest/tauri_plugin_global_shortcut/).
    **Proposed edit:** settings.md §10 distinguishes local physical `keybindings` from Windows-supported `bossKey.shortcut`; reject unsupported/ambiguous boss tokens with `SHORTCUT_INVALID` and state layout-dependent global behavior. Toggle only on `ShortcutState::Pressed`. For `boss_set_shortcut`/`boss_set_enabled`, delay settings publication until registration/persistence succeeds; explicitly attempt compensating rollback on IO/unregister failure. If rollback fails, reject with `INTERNAL`, expose actual `BossKeyStatus` through `boss_get_status`, and permit `boss://register-failed {shortcut,error}` with `error.code = "INTERNAL"` for this exceptional command failure. Update errors.md's no-side-effects exception and events.md's command-failure prohibition accordingly. No elevation is required; reserved/occupied chords remain normal errors.

27. **[CHANGE] Future TXT iframe origin behavior needs correction before M4.**
    An iframe navigated directly to `http://asset.localhost/...` is cross-origin to the app UI; `sandbox="allow-same-origin"` preserves that origin, not the parent's. The UI cannot then inject reading CSS or attach locator/key listeners as PRD §10.4 requires.
    **Proposed edit:** commands.md “Book bytes” says `TxtSection.path` is fetched using `convertFileSrc`, then rendered through a UI-created Blob URL or `srcdoc` in the existing no-scripts sandbox, preserving parent access. Keep the current payload field names. Define equivalent sandbox/CSP enforcement for these generated documents and EPUB Blob sections; retain the exact HTTP asset origin unless `use_https_scheme` and CSP are changed together.

28. **[CHANGE] Move the minimal settings loader into the M0 dependency boundary.**
    Startup already consumes `window.titleBar` and `library.folder`, while M2.1a introduces the settings implementation and PRD M2.1b still assigns migrations to the UI. This creates two possible owners/loaders before the lanes meet.
    **Proposed edit:** README's milestone/decision text explicitly requires the Rust profile-aware settings loader, repairs, defaults and migration ownership in M0.1; M2 adds generic write commands and full validation/UI. Update the cited M2.1b responsibility to UI input clamping/store/debounce only, with Rust migration authority. Temporary KV remaining separate until M3 is consistent.

29. **[NOTE] Verification and remaining evidence.**
    `node scripts/contract-check.mjs` passed: all 23 M0–M3 examples, 11 event example groups, settings/default/schema consistency, SQL creation, user_version and cascade checks. Additional in-memory Node SQLite probes reproduced nullable primary keys, fractional INTEGER storage, scalar locator JSON and bookmark-id reuse; path-regex probes reproduced acceptance of a UNC server without a share. Rust/TS field/enum comparison and `MergePatch` analysis were static; no app build, Rust contract round-trip harness, strict TypeScript compiler run, or real Snap/DPI test was performed. Online references were checked against stable API documentation and implementation sources; development-branch examples are identified above. Dany_PM should incorporate accepted behavioral/shape changes with a minor contract version bump and matching examples before implementation.
